## 1. Objective
Design and implement a high-performance **Hybrid Python + Rust (`PyO3` / `maturin`)** architecture (`quast_core`) to eliminate Python GIL bottlenecks during multi-file `.docx` batch conversion, multi-megabyte formula tokenization, and mathematical image preprocessing, while ensuring 100% **ISO 80000-2** compliance for 2D stretchy delimiters in converted Word equations.

---

## 2. Scope & Execution Steps

### Step 1: Cargo & Maturin Workspace Configuration
1. Created `Cargo.toml` and `pyproject.toml` configured for `maturin` (`abi3-py38` stable ABI compatible with Python 3.8 through 3.13+).
2. Configured release profile optimizations (`opt-level = 3`, `lto = "fat"`, `codegen-units = 1`, `panic = "abort"`, `strip = true`).
3. Created Python wrapper and type stubs in `python/quast_core/{__init__.py, _quast_core.pyi}` and CI workflow `.github/workflows/wheels.yml`.

### Step 2: Module 1 — High-Speed Formula Tokenizer (`rust_core/src/tokenizer/`)
1. Implemented a single-pass state machine scanner (`scanner.rs`) with `memchr` SIMD acceleration to scan text zero-copy (`&str`), shielding fenced code blocks (` ```...``` `) and inline code (`` `...` ``), handling escaped `\$`, avoiding false currency matches (`$100`), and detecting raw LaTeX expressions (`is_pure_latex_formula`).
2. Implemented `normalizer.rs` using static `regex::Regex` (`once_cell::Lazy`) to normalize spacing on trigonometric and logarithmic functions (`\sin`, `\cos`, `\log`, etc.).

### Step 3: Module 2 — Parallel DOCX Batch & XML Streaming Engine (`rust_core/src/docx_engine/`)
1. Implemented `preview_patch.rs` and `xml_stream.rs` using `zip` (`raw_copy_file` for zero-recompression media copying) and `quick-xml` streaming events to preserve `<w:pPr>` formatting and inject `<m:oMath>` blocks without loading full DOM trees into memory.
2. Implemented `batch_runner.rs` using `rayon::par_iter()` and a **Two-Phase Deduplication Cache**:
   - Phase 1: Parallel extraction of the unique formula set across all `.docx` files without holding the Python GIL.
   - Phase 2: Unique formula compilation into an OMML lookup map.
   - Phase 3: Parallel `rayon` streaming replacement and ZIP repackaging with atomic progress reporting (`AtomicUsize`).

### Step 4: Module 3 — Pure-Rust Math Image Preprocessing (`rust_core/src/image_proc/`)
1. Implemented `denoise.rs` (branchless 9-element sorting network 3x3 median filter), `binarize.rs` ($O(1)$ per-pixel adaptive Sauvola thresholding via integral images parallelized with `rayon`), and `crop.rs` (auto-bounding-box foreground crop with padding).
2. Exposed `preprocess_formula_image` over zero-copy Python buffer protocol (`&[u8]` -> `PyBytes::new_bound_with`).

### Step 5: ISO 80000-2 Stretchy 2D Delimiter Transformation (`fix_mathml_tree`)
1. Removed legacy string replacements that converted `<mo>(</mo>` into flat `<mi>(</mi>`.
2. Implemented AST grouping of matched `()`, `[]`, `{}` pairs into sub-`<mrow>` elements and lifted superscript/subscript nodes on closing delimiters (`(-1)^k`) so `MML2OMML.XSL` generates true 2D stretchy `<m:d>` elements wrapped inside `<m:sSup>`.

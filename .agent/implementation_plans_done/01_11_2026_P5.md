## 1. Objective
Design and implement an end-to-end **Offline Mathematical Image OCR-to-OMML Pipeline (`image_omml_engine.py`)** for the `IMAGE` tab—combining Rust `quast_core` image preprocessing, multi-tier offline formula OCR, 2D spatial layout reconstruction, post-OCR LaTeX normalization, and direct AST-to-OMML compilation—while throttling background CPU/GPU thread usage to guarantee 60+ FPS UI responsiveness and zero memory leaks.

---

## 2. Scope & Execution Steps

### Step 1: Rust Dark-Background Auto-Inversion (`rust_core/src/image_proc/mod.rs`)
1. Enhanced the Rust image preprocessing pipeline to analyze border and median pixel luminance before Sauvola adaptive binarization.
2. Automatically inverted dark-background screenshots (>55% dark pixels, e.g., Dark Mode equation captures) into crisp black-foreground-on-white-background images prior to 3x3 median filtering, Sauvola thresholding, and auto-cropping.

### Step 2: Multi-Tier Math Image OCR Engine (`image_omml_engine.py`)
1. **Multi-Mode Image Preprocessor (`preprocess_for_math_ocr`)**:
   - Combines `quast_core.preprocess_formula_image` with Lanczos upscaling for small formula captures (`height < 48px`) to preserve subscript/superscript legibility.
2. **Singleton Lazy-Loaded `MathImageOCREngine`**:
   - **Tier 1 (Primary Deep Math OCR)**: Uses `FormulaRecognition` (`PP-FormulaNet` / `RapidLaTeXOCR`) to recognize 2D mathematical structures directly into LaTeX.
   - **Tier 2 (`Structural2DMathExtractor` Fallback)**: Uses Connected Components and 2D spatial bounding-box layout analysis (detecting horizontal fraction bars with $w/h \ge 4.5$, radicals $\sqrt{\cdot}$, superscript/subscript vertical offsets relative to baseline) paired with locally cached `PP-OCRv6_medium` weights so offline recognition always succeeds without network access.
3. **Post-OCR LaTeX Normalizer (`OCRLaTeXNormalizer`)**:
   - Repairs unbalanced `\left` / `\right` and `{...}` delimiters, strips display-only wrappers (`\displaystyle`, `\mbox`), and normalizes Unicode math symbols (`×` -> `\times`, `÷` -> `\div`, `≤` -> `\le`, `≥` -> `\ge`).
4. **Direct OMML Compilation**:
   - Feeds normalized LaTeX directly into `latex_omml_engine.compile_raw_latex_for_studio` with inline alignment (`is_block = False` by default).

### Step 3: Throttled Background Worker & Memory Release (`ImageOcrWorker` in `app.py`)
1. Restricted OpenMP / MKL / Paddle threads to 1 (`OMP_NUM_THREADS = '1'`, `PADDLE_NUM_THREADS = '1'`, `OPENBLAS_NUM_THREADS = '1'`) and set `ImageOcrWorker` to `QThread.LowPriority` so the main Qt/WebEngine UI thread stays locked at 60–144 FPS during OCR.
2. Added `release_memory()` (`gc.collect()`) inside a `finally:` block after every OCR job to prevent RAM accumulation.

### Step 4: `IMAGE` Tab UI Refinements (`UI/UI_updated.html`)
1. Removed redundant buttons (`Browse`, `Enhance`, `Original`, `OMML XML`, `Save .docx`) and pixel dimension badges.

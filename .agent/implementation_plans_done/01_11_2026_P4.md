## 1. Objective
Design and implement a standalone **Direct LaTeX-to-OMML AST Compiler (`latex_omml_engine.py`)** for the `LATEX` tab—completely eliminating its dependency on `latex2mathml` and `MML2OMML.XSL`—and fix the `"COPY OMML"` workflow so equations paste directly into Microsoft Word as native 2D Word Equations with accurate inline vs. display alignment.

---

## 2. Scope & Execution Steps

### Step 1: 5-Stage Direct LaTeX-to-OMML Compiler (`latex_omml_engine.py`)
1. **Stage 1 — Multi-Mode Preprocessor & Segmenter**:
   - Automatically distinguishes pure raw LaTeX (without `$` delimiters), multi-line equation blocks, and mixed prose/math segments (`$...$`, `$$...$$`, `\(...\)`, `\[...\]`).
   - Normalizes macros (`\dfrac`, `\tfrac`, `\cfrac`, `\implies`, `\iff`, `\to`, `\mathbb`, `\mathcal`, `\mathbf`, `\mathrm`, `\text`, `\operatorname`).
2. **Stage 2 — `LaTeXLexer`**:
   - Tokenizes commands, groups (`{}`), optional arguments (`[]`), superscripts (`^`), subscripts (`_`), primes (`'`), alignment tabs (`&`), row separators (`\\`), numbers, identifiers, operators, and delimiters.
3. **Stage 3 — Recursive-Descent `LaTeXASTParser`**:
   - Constructs strongly typed AST nodes: `RowNode`, `FracNode`, `BinomNode`, `SqrtNode`, `ScriptNode`, `NaryNode` (`\sum`, `\prod`, `\int`, `\iint`, `\oint`), `LimNode` (`\lim`, `\max`, `\min`, `\sup`, `\inf`), `FuncNode` (`\sin`, `\cos`, `\ln`, `\log` with upright ISO 80000-2 function names `<m:sty m:val="p"/>`), `DelimNode` (stretchy 2D `<m:d>` for both `\left...\right` and regular `(...)`, `[...]`, `\{...\}`), `AccentNode` (`\hat`, `\vec`, `\bar`, `\overline`, `\widetilde`), `MatrixNode`, `CasesNode`, `EqArrayNode` (`aligned`, `align`, `split`), and `TextNode`.
4. **Stage 4 — Direct `OMMLBuilder`**:
   - Emits clean `<m:oMath>` (inline) and `<m:oMathPara>` (display/multi-line) XML trees directly via `lxml.etree`.
5. **Stage 5 — `MathMLPreviewBuilder`**:
   - Generates presentation MathML from the same AST for live visual rendering alongside KaTeX.

### Step 2: Native Windows Clipboard Integration (`copy_omml_to_clipboard` in `app.py`)
1. Replaced sandboxed JavaScript `navigator.clipboard.writeText()` (which silently failed inside `QWebEngineView` and left old screenshots in the clipboard) with a native Python `@pyqtSlot` using `win32clipboard`.
2. Registered both `"MathML Presentation"` and `CF_UNICODETEXT` clipboard formats simultaneously so pasting (`Ctrl+V`) into Microsoft Word creates a native 2D Word Equation while pasting into text/code editors pastes the raw OMML XML.

### Step 3: Inline vs. Display Equation Alignment in Microsoft Word
1. Classified input expressions into `is_block = True` (only when explicitly wrapped in `$$...$$`, `\[...\]`, or display environments) vs. `is_block = False` (raw un-delimited LaTeX or `$...$`).
2. Generated `display="inline"` MathML and inline `<m:oMath>` when `is_block = False`, ensuring Word pastes inline (`wdOMathJcInline = 7`) within a sentence rather than forcing block-level center alignment (`wdOMathJcCenter = 1`).

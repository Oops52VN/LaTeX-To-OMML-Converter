## 1. Objective
Accelerate `.docx` batch formula conversion by 3x–10x, eliminate post-conversion PDF preview hangs caused by Windows file-sharing locks (`os error 32`) and full-document repagination stalls, and implement deterministic percentage milestones on the conversion progress bar.

---

## 2. Scope & Execution Steps

### Step 1: 2-Tier Formula OMML Cache & Single-Pass $O(N)$ MathML Tree Normalization
1. **Pre-compiled Module-Level Regexes**:
   - Hoisted `_FUNC_PATTERN_RE`, `_CODE_BLOCK_TRIPLE_RE`, `_CODE_BLOCK_SINGLE_RE`, and `_MATH_SPLIT_RE` to module-level `re.compile()` constants in `app.py`.
2. **Single-Pass $O(N)$ `fix_mathml_tree`**:
   - Replaced the $O(50 \cdot N^2)$ `while changed:` XPath loop with a single-pass bottom-up post-order traversal over `<mrow>` and `<math>` nodes (1.61x faster, 100% byte-identical output).
3. **2-Tier `FormulaOmmlCache` (RAM + Persistent Disk)**:
   - Cached compiled `latex -> omml_xml` mappings in an in-memory dictionary backed by `%TEMP%/quast_preview_cache/omml_formula_cache.json` and disabled `pretty_print=True` during batch serialization (reducing XML size by 25% and accelerating repeated 1,000-formula batches from 4.05s to **0.02s**).

### Step 2: Word COM Isolation, Fast-Path Open & Queue Pre-emption (`PersistentWordPdfEngine`)
1. **Eliminated `doc.ComputeStatistics(2)`**:
   - Removed the blocking `ComputeStatistics(2)` call that forced Microsoft Word to repaginate the entire document before exporting.
2. **Isolated `%TEMP%` Copy to Prevent Windows `os error 32`**:
   - Copied target `.docx` files to `%TEMP%/quast_preview_src_<uuid>.docx` (<3ms) before opening in Word COM with `ReadOnly=True` and `OpenAndRepair=False` (`Pagination = False`, `ShowAnimation = False`), preventing Word from locking input/output `.docx` files during re-conversion.
3. **Queue Cancellation & Pre-emption (`cancel_pending_requests`)**:
   - Added immediate queue cancellation and `active_req_id` invalidation whenever a new batch conversion starts or the user selects a different file, plus a safety timeout guard in `UI/UI_updated.html` and deterministic `self.word_pid` process cleanup on exit.

### Step 3: Static Progress Bar Milestones & File List UI Polish
1. Configured monotonically increasing progress milestones (`0% -> 18% -> 35% -> 52% -> 70% -> 85% -> 100%`) with concise static status messages.
2. Removed bullet markers (`list-style: none`) from file lists, removed preview blur effects, and reduced WebView2/iframe fallback timers (`800ms -> 150ms` in `edge_pdf_viewer.py` and `300ms -> 120ms` in `UI/UI_updated.html`).

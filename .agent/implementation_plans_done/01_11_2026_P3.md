## 1. Objective
Replace the legacy non-interactive `QWebEngineView` PDF previewer with a native **Microsoft Edge WebView2 PDF Viewer** (`ICoreWebView2Controller` powered by Adobe Acrobat / `mspdf.dll` inside Edge WebView2 Runtime) and eliminate cold-start Word COM latency by introducing a pre-warmed **`PersistentWordPdfEngine`** with progressive preview export and deterministic page-layout preservation.

---

## 2. Scope & Execution Steps

### Step 1: Native Edge WebView2 PDF Host (`edge_pdf_viewer.py`)
1. Created `EdgePdfPreviewHost(QWidget)` using pure Python `ctypes` COM vtable bindings against `WebView2Loader.dll` (`CreateCoreWebView2EnvironmentWithOptions`).
2. Attached `ICoreWebView2Controller` directly to the native Win32 child window handle (`int(self.winId())`) inside `WebMainWindow`.
3. Registered `NavigationCompleted` event callbacks to emit `pdf_loaded_signal` so the UI hides the loading overlay at the exact moment PDF rendering completes.
4. Implemented `load_pdf(pdf_path)`, `update_geometry_dip(x, y, w, h, dpr)`, and `set_viewer_visible(visible)` with automatic fallback to `<iframe>` if WebView2 Runtime is unavailable on the host machine.

### Step 2: Persistent Word COM Engine (`PersistentWordPdfEngine` in `app.py`)
1. Replaced one-off per-file `Word.Application` COM instantiations with a persistent background STA worker thread (`PersistentWordPdfEngine`) that keeps a single headless `Word.Application` instance warm across the application lifecycle (`CheckSpellingAsYouType = False`, `CheckGrammarAsYouType = False`).
2. Removed all preprocessing overrides that altered document margins, paper sizes, or fonts so exported preview PDFs preserve 100% of the original `.docx` layout.
3. Implemented `PreviewCacheManager` keyed by `(canonical_path, mtime_ns, file_size)` for instant switching between cached input and output `.docx` previews.

### Step 3: Frontend Geometry Synchronization (`UI/UI_updated.html`)
1. Added `syncEdgePdfViewerRect()` using `ResizeObserver` and `getBoundingClientRect()` on `#view-pdf` to synchronize native Win32 child window coordinates via `backend.update_word_rect('pdf-preview', x, y, width, height)`.
2. Coordinated `backend.set_word_visible('pdf-preview', ...)` with loading spinner visibility and tab switches (`FILE`, `LATEX`, `IMAGE`) so the native HWND overlay never obscures HTML modals, spinners, or other tabs.

## 1. Root Cause Analysis

1. **Application Icon Transparency Regression (`resources/icons/app.ico`, `build_release.py`)**:
   - `resources/icons/logo.jpg` has an opaque white background, while `resources/UI/assets/logo.png` had its white background removed to transparent RGBA solely for CSS theme inversion inside `UI.html`.
   - `build_release.py` generated `resources/icons/app.ico` directly from `logo.png`, turning the icon background transparent across all 7 resolutions (`16x16` to `256x256`).
2. **Packaged Image Tab OCR Failure (`build_release.py`, `app/image_omml_engine.py`, `app/app.py`)**:
   - `paddlex.utils.deps.is_dep_available()` and `@class_requires_deps(...)` validate runtime dependencies via `importlib.metadata.version(dep)` (`pypdfium2`, `tokenizers`, `opencv-contrib-python`, `safetensors`, `pillow`, `PyYAML`, `requests`, etc.).
   - PyInstaller `--collect-all` in `build_release.py` only collected metadata for `quast_core`, `docx`, `latex2mathml`, `paddle`, `paddleocr`, `paddlex`, and `cv2`, omitting `.dist-info` metadata for `pypdfium2`, `tokenizers`, and other PaddleX runtime dependencies.
   - As a result, `FormulaRecognition(model_name="PP-FormulaNet_plus-M", model_dir=...)` raised `DependencyError` inside the packaged executable, `MathImageOCREngine._ensure_predictor()` failed silently, and `recognize()` fell back to `_recognize_structural_2d()`, returning a hardcoded dummy formula (`x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}`) for every image.
   - Additionally, `--windowed` PyInstaller builds leave `sys.stdout` and `sys.stderr` as `None`, risking `NoneType` stream errors in logging/progress libraries.

## 2. Changes Applied

- **`build_release.py`**:
  - Added `_ico_has_transparency()` and updated `ensure_icon()` to regenerate `resources/icons/app.ico` whenever missing or transparent, compositing `resources/UI/assets/logo.png` onto an opaque solid white `(255, 255, 255, 255)` background (falling back to `resources/icons/logo.jpg`) and saving as RGB ICO across sizes `16`–`256`.
  - Added `_collect_installed_ocr_metadata()` (combining `paddlex.utils.deps.BASE_DEP_SPECS` / `EXTRAS` and core OCR/runtime distributions) and updated `run_pyinstaller()` to pass `--collect-all` for `tokenizers`, `safetensors`, `pypdfium2`, `pypdfium2_raw`, `ftfy`, `shapely`, `pyclipper`, `imagesize` (filtered via `importlib.util.find_spec`) and `--copy-metadata` for all 49 installed runtime distributions.
- **`resources/icons/app.ico`**:
  - Regenerated with solid opaque white background across all 7 resolutions (`alpha=(255, 255)`).
- **`app/app.py`**:
  - Redirected `None` `sys.stdout`/`sys.stderr` to `os.devnull` at startup for `--windowed` frozen builds.
  - Updated `Backend.start_image_ocr()` to remove `worker` from `active_workers` on `worker.finished` rather than inside `on_done`.
  - Added `sys._MEIPASS` lookup to `Backend.get_readme_markdown()`.
  - Added `--check-ocr` CLI self-test branch for headless verification of the frozen binary.
- **`app/image_omml_engine.py`**:
  - Added writable `PADDLE_PDX_CACHE_HOME` fallback to `tempfile.gettempdir()` if `~/.paddlex` cannot be created.
  - Updated `MathImageOCREngine.recognize()` to return `success: False` with the real diagnostic error when `PP-FormulaNet` fails instead of silently returning the hardcoded Tier 2 placeholder formula.
- **`tree.txt`**:
  - Updated `releases/` section to reflect the compiled `OMML_Converter_Setup_v11.18.2026.exe` installer.
